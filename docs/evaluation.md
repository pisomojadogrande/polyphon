# Milestone 1 evaluation

## What was actually measured

2026-10-11, Linux x86-64, Node 24.19.0, CPython 3.11.17, Basic Pitch 0.4.0, ONNX CPU. Synthetic WAVs are generated by `python/make_fixture.py` at 22,050 Hz. Every transcription starts a fresh Python process. The first run also paid the audio-processing JIT cost; later processes reused the compilation cache. Peak RSS includes imported native libraries, not just the model.

| Diagnostic input | Audio seconds | Worker seconds | Peak RSS MiB | Expected notes | Detected notes | Pitch/onset matches |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Single-note melody (first/cold) | 5 | 13.26 | 861.60 | 4 | 4 | 4/4 |
| Three-note chords (cache warm) | 5 | 2.93 | 761.36 | 12 | 13 | 12/12 |
| Silence (cache warm) | 2 | 2.74 | 755.80 | 0 | 0 | n/a |

Matching here means identical MIDI pitch and onset within 150 ms, one detected note per expected event. These are diagnostic checks, not an established musical accuracy metric. Chords produced an extra note, demonstrating that even simple generated inputs can yield artifacts. The melody smoke additionally verifies a readable MIDI, positive durations, consistency with the report note count, and at least three expected pitches.

The first melody's stage times: loading 1.95s, decoding/JIT 11.21s, inference 0.09s, note extraction 0.003s, writing 0.003s. Startup and imports dominate these tiny clips. Do not extrapolate these numbers to a three-minute ensemble, AWS cost, or a $5/month budget. Roughly 0.75–0.86 GiB RSS already argues against assuming very small worker memory without measurement.

**Not yet evaluated:** actual solo singing, multiple a cappella voices, voices with instruments, normal three-minute recordings, cloud cost/runtime, score quality, and usefulness to the user. No private recordings were supplied. No human listening assessment is claimed from the automated browser test.

## Your first listening session

Use three 10–30 second excerpts: (1) isolated voice, (2) a cappella ensemble, (3) voice plus instruments. Start with WAV/FLAC. Record known key/tempo/meter and voice descriptions, but remember only tempo/meter affect MIDI metadata in this phase. Keep clip selection stable when comparing settings.

For each clip:
1. Listen to the original once, then to the MIDI at normal speed.
2. Try slower playback and seek to passages where notes overlap.
3. Rate usefulness from **1 to 5**: 1 = unusable/no recognizable line; 2 = fragments with major errors; 3 = recognizable rough sketch; 4 = useful starting point with corrections; 5 = close enough for the intended task.
4. Note missing melody tones, extra/harmonic notes, merged voices, onset/duration errors, and any long rests/noise converted into notes. Include approximate timestamps.
5. Save duration, worker runtime, peak RSS, note count, and whether it was the first/cold run. Preserve the report and downloaded MIDI.

Use the batch runner described in README to get `evaluation.json` containing all machine measurements, then fill `usefulnessRating` and `listeningNotes`. For a single web job, copy the fields below into a local feedback note. Do not commit private audio or generated results to the public repository.

After short clips are useful, evaluate longer excerpts and eventually a typical three-minute recording. Compare repeated runs on the same machine and cache state. We will decide whether Basic Pitch needs preprocessing/source separation or replacement before picking AWS compute. Supply anonymized reports/notes first; share recordings only if you want them used for further evaluation.

## Python 3.14 repair regression (2026-10-17)
The ONNX-only package and modern numerical stack were tested on CPython 3.14.8 and 3.11.17 against the original synthetic MIDI baseline. Melody, chords, and silence retained their note counts, pitches, timing, velocities, and pitch bends within the documented tight tolerances. Using the fresh locked pip installation, the first Python 3.14 melody run took 11.76s / 427.14 MiB peak worker RSS; subsequent fresh workers with a warm audio JIT cache took 1.29s / 318.53 MiB for chords and 1.30s / 317.37 MiB for silence. These are diagnostic results, not a representative-recording or cloud sizing claim. Historical measurements above used the old TensorFlow-importing environment. See `python314.md` for dependency and regression details. No new human listening assessment is claimed.
